Thay supabase-js bằng Drizzle, và thêm tầng API

Tưởng là đổi thư viện, hóa ra là chuyển trách nhiệm phân quyền từ database lên backend. Làm thử với tính năng linh vật (pet).

Trạng thái: đã chạy thật. 20 test qua (5 trên Postgres thật, 15 ở route), TypeScript và ESLint không lỗi.

Vấn đề: code cũ chạy trong trình duyệt

File lib/pet/pet-repo.ts gọi thẳng Supabase từ trình duyệt, và RLS là lớp bảo vệ duy nhất. Drizzle kết nối bằng chuỗi có mật khẩu, nên không thể chạy trong trình duyệt. Ta buộc phải thêm một tầng ở giữa.

Code đã viết

      
Sáu việc, mỗi việc một file nhỏ. Tất cả nằm trong repo fork, nhánh learn/step-1-postgres.


      
1. Schema Drizzle: lib/db/schema.ts

      
drizzle-kit pull sinh được schema từ database, nhưng bản sinh có nhiều thứ thừa (15 sequence của bảng khác, khoá ngoại trỏ tới bảng chưa khai báo). Ta chọn lọc rồi viết tay. Cột species dùng lại PET_SPECIES của code cũ nên kiểu TypeScript khớp tuyệt đối.


export const userPet = pgTable("user_pet", {
  userId: uuid("user_id").primaryKey(),
  species: text("species", { enum: PET_SPECIES }).notNull(),
  name: text("name").notNull(),
  adoptedAt: timestamp("adopted_at", { withTimezone: true, mode: "date" })
    .defaultNow().notNull(),
  baseXp: integer("base_xp").default(0).notNull(),
  updatedAt: timestamp("updated_at", { withTimezone: true, mode: "date" })
    .defaultNow().notNull(),
});


      
2. Connection pool: lib/db/client.ts

      
Mở kết nối Postgres tốn kém, nên dùng một pool dùng chung. Ở chế độ dev, Next.js nạp lại module liên tục, nên pool được gắn vào globalThis để không mở thêm kết nối mỗi lần nạp lại.


globalForDb.__pgPool ??= createPool();   // chỉ tạo nếu chưa có


      
3. Truy cập dữ liệu: lib/pet/pet-db.ts

      
Hai hàm. db được truyền vào làm tham số (dependency injection) để test dùng được kết nối riêng. savePet là upsert: chèn, nếu trùng khoá chính thì cập nhật.


export async function loadPet(db: Db, userId: string) {
  const [row] = await db.select().from(userPet)
    .where(eq(userPet.userId, userId)).limit(1);   // luôn có where user_id
  ...
}

await db.insert(userPet).values({ userId, ...fields })
  .onConflictDoUpdate({ target: userPet.userId, set: fields });


      
4. Route: app/api/pet/route.ts

      
Ba tầng chặn theo thứ tự: xác thực (401), validate (400), rồi mới chạm database. userId luôn lấy từ phiên.


const user = await getCurrentUser();
if (!user) return Response.json({ error: "auth_required" }, { status: 401 });

const parsed = petBodySchema.safeParse(await req.json().catch(() => null));
if (!parsed.success) return Response.json({ error: "invalid_request" }, { status: 400 });

await savePet(getDb(), user.id, parsed.data);   // user.id, không phải body

Bốn bài học

      

        
Đường biên giữ nguyên
Nhờ pet-repo.ts giữ chữ ký hàm, giao diện không biết bên dưới đã đổi. Đó là lý do nên có tầng repo.

        
Theo quy ước có sẵn
Kế hoạch ghi 422 cho dữ liệu sai, nhưng repo đã dùng 400 invalid_request. Ta theo repo, vì nhất quán quan trọng hơn sách giáo khoa.

        
Truyền db vào hàm
Hàm nhận db thay vì tự lấy pool, nên test chạy với kết nối riêng và route mock được. Hay gặp trong phỏng vấn.

        
Bẫy công cụ
Vitest 4 cần Node 20 trở lên (máy đang Node 18), và npm trên Windows có thể thiếu file nhị phân của rolldown. Đã ghi vào runbook.

      

    


    

      
Bài tập của bạn: chuyển lyric-offset-repo.ts

      
Cùng khuôn với pet, nhưng có hai điểm khó mới. Bạn tự làm, tôi chỉ review.

      

        
Đề

        
File lib/user-data/lyric-offset-repo.ts có hai hàm gọi thẳng Supabase từ trình duyệt: fetchRemoteOffset(videoId) và pushRemoteOffset(videoId, offsetSec). Chuyển chúng sang Drizzle qua một route /api/lyric-offset, giữ nguyên chữ ký hàm và cách xử lý lỗi (lỗi thì bỏ qua, trả null).

        
Hai điểm khó

        
Khoá chính ghép. Bảng user_song_progress có khoá chính (user_id, video_id), nên onConflictDoUpdate nhận target là mảng hai cột.

        
Upsert chỉ một cột. Hàng này còn lưu tiến độ nghe. Phần set chỉ được chứa lyricOffsetSec và updatedAt, nếu không bạn xoá mất tiến độ của người dùng.
