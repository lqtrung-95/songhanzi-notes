Chạy 70 migration trên Postgres thuần

Mục tiêu: hiểu Supabase thực sự cho bạn những gì ở tầng database, rồi tự dựng lại phần đó trong Docker.

Trạng thái: đã chạy thật. 68 migration chạy thành công trên Postgres 17 trong Docker và RLS đã được kiểm chứng (xem mục Chạy thật).

Supabase là gì, nhìn từ bên trong

Supabase là một gói gồm Postgres và một số dịch vụ đặt cạnh nó. Chỉ riêng Postgres là thứ ta giữ nguyên. Mỗi dịch vụ còn lại sẽ được thay ở một bước riêng.

Vì sao migration nguyên bản chạy lỗi

Lấy file 20260925000005_user_accounts.sql làm ví dụ. Nó dùng 4 thứ mà Postgres thuần không có:

DòngCâu lệnhThiếu gì
5references auth.users (id)Schema auth và bảng users
94for all to authenticatedRole authenticated
95(select auth.uid()) = user_idHàm auth.uid()
195grant execute ... to service_roleRole service_role

Toàn repo: 25 file migration nhắc auth.*, 28 chỗ khai báo security definer, 1 chỗ dùng schema extensions, 1 chỗ chèn vào storage.buckets, 2 chỗ thêm bảng vào publication supabase_realtime.

Lớp shim: dựng lại 6 mảnh

Thay vì sửa 70 file migration, ta tạo đúng những thứ chúng cần trước khi chạy. File nằm ở db/compat/00_supabase_shim.sql.

1

Ba schema

Ngăn chứa tên: auth, extensions, storage.

create schema if not exists auth;
2

Ba role

Nhãn để gán quyền. service_role bỏ qua RLS, dành cho server.

create role anon nologin;
create role authenticated nologin;
create role service_role
  nologin bypassrls;
3

auth.users

Bảng thường, để khoá ngoại hoạt động. Bước 4 sẽ thay.

create table auth.users (
  id uuid primary key
    default gen_random_uuid(),
  email text, is_anonymous boolean
);
4

auth.uid()

Trả về "người đang gọi là ai", đọc từ biến phiên. RLS dựa vào hàm này.

select nullif(
  current_setting(
   'request.jwt.claim.sub', true),
  '')::uuid
5

storage.buckets

Migration chèn bucket avatars vào đây.

create table storage.buckets (
  id text primary key,
  name text, public boolean
);
6

Publication realtime

Danh sách bảng mà Postgres sao chép thay đổi ra ngoài. Chỉ cần tồn tại.

create publication
  supabase_realtime;
Ý chính: Supabase không có phép màu ở tầng database. Phần "đắt" nằm ở Auth, Realtime và PostgREST, là những thứ ta sẽ thay ở các bước sau.

Demo: RLS lọc hàng như thế nào

RLS (Row Level Security) là luật nằm trong Postgres: "mỗi người chỉ thấy hàng của mình". Bảng bên dưới là user_cards với dữ liệu minh hoạ. Chọn danh tính, bật hoặc tắt RLS, rồi xem kết quả của select * from user_cards.

Chạy thật

      
Làm theo thứ tự. Mỗi lệnh chạy ở thư mục songhanzi-fullstack.

      
# 1. Khởi động Postgres (cần Docker Desktop đang chạy)
docker compose up -d

# 2. Chạy shim và 70 migration
bash db/apply-migrations.sh

# 3. Vào psql trong container để tự kiểm tra
docker exec -it songhanzi-db psql -U postgres -d songhanzi

      
Trong psql, thử các lệnh sau và ghi lại kết quả vào mục ghi chú:

      
\dt public.*                                   -- liệt kê bảng
select count(*) from public.schema_migrations; -- số migration đã chạy
\d public.user_cards                           -- cấu trúc bảng, index, policy
