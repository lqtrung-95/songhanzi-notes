Backend là gì, và một dev frontend cần biết những gì

Mọi khái niệm dưới đây đều gắn với một chỗ cụ thể trong SongHanzi. Đọc xong mỗi mục, hãy mở file được nhắc tên để thấy nó trong code thật.

Một request đi qua những tầng nào

Khi bạn bấm "Lưu từ vựng" trên giao diện, trình duyệt gửi một request. Backend là mọi thứ xảy ra từ lúc request tới nơi cho đến khi có phản hồi.

Thói quen quan trọng nhất: với mỗi tính năng, hãy tự hỏi "request đi qua tầng nào, tầng nào chặn nó nếu sai?". Lỗ hổng bảo mật gần như luôn là một tầng bị bỏ sót.

HTTP và status code

HTTP là cách trình duyệt và server nói chuyện. Một request có method, đường dẫn, header và (đôi khi) body. Phản hồi có status code, header và body.

POST /api/practice/score HTTP/1.1
Cookie: sb-session=...            ← danh tính nằm ở header
Content-Type: application/json

{"videoId":"demo","score":80}

HTTP/1.1 201 Created              ← status code
Content-Type: application/json

{"ok":true}

GETĐọcCó, không đổi dữ liệuKhông sao
POSTTạo mới, hành độngKhôngCó thể tạo trùng
PUTThay cả tài nguyênKhôngKhông sao (idempotent)
PATCHSửa một phầnKhôngTuỳ cách viết
DELETEXoáKhôngKhông sao (xoá lần 2 vẫn "đã xoá")

Tra nhanh status code

Demo: server chọn status code nào?

401, 403, 404, 422 là nhóm hay bị nhầm. Đặt tình huống và xem server nên trả gì.

Có hai trường phái cho trường hợp "của người khác": 403 (nói rõ bị cấm) hoặc 404 (giấu sự tồn tại). Với dữ liệu riêng tư, 404 an toàn hơn vì không để lộ rằng tài nguyên có thật.

Thiết kế API

Đặt tên theo tài nguyên

GET /api/videos/123, POST /api/feedback. Danh từ, không phải động từ (/getVideo).

Phản hồi lỗi thống nhất

Luôn cùng một dạng, ví dụ {"error":"..."} kèm status đúng. Frontend xử lý một kiểu thay vì mười kiểu.

Phân trang

Danh sách dài phải có giới hạn (limit, cursor). Không bao giờ trả "tất cả".

Validate đầu vào

Mọi thứ từ client đều không đáng tin. Kiểm bằng schema (Zod trong repo), không kiểm bằng niềm tin.

Idempotency

Người dùng bấm hai lần, mạng retry. Thao tác tạo nên chịu được việc gọi lặp (khoá duy nhất, on conflict do nothing).

Tách tầng

Route handler chỉ nhận và trả. Logic nằm ở lib/, truy cập DB nằm ở repo. Dễ test, dễ thay Supabase.

Xác thực và phân quyền

Xác thực (authentication) trả lời "bạn là ai". Phân quyền (authorization) trả lời "bạn được làm gì". Hai thứ này khác nhau, và lỗi phổ biến nhất là có đăng nhập nhưng quên kiểm quyền.

Session (cookie)JWT
Lưu ởServer nhớ, cookie chỉ giữ IDToken tự chứa thông tin, ký bằng khoá
Thu hồiDễ: xoá phiên ở serverKhó: phải chờ hết hạn hoặc giữ danh sách đen
Hợp vớiWeb một domainNhiều dịch vụ, mobile

Cookie đăng nhập cần ba cờ: HttpOnly (JavaScript không đọc được, chống XSS đánh cắp), Secure (chỉ gửi qua HTTPS), SameSite (hạn chế gửi chéo site, chống CSRF).

OAuth (đăng nhập Google) hiểu gọn: app không bao giờ thấy mật khẩu Google. Google xác minh người dùng rồi trả cho app một mã, app đổi mã đó lấy thông tin tài khoản. SongHanzi xử lý bước này ở app/auth/callback/route.ts.

Database

Khoá chính, khoá ngoại

Mỗi hàng có định danh duy nhất; khoá ngoại bảo đảm không có hàng mồ côi. Xem references auth.users ở bước 1.

Index

Như mục lục sách: tìm nhanh thay vì đọc cả bảng. Đánh đúng cột bạn hay lọc (user_cards_due_idx). Index thừa làm ghi chậm.

Transaction (ACID)

Nhiều lệnh thành một khối: hoặc cùng thành công hoặc cùng huỷ. Hàm merge_user_data chạy trong một giao dịch vì lý do đó.

Truy vấn N+1

Lấy 50 bài rồi gọi DB thêm 50 lần cho từng bài. Sửa bằng join hoặc lấy gộp một lần.

Migration

Thay đổi schema được ghi thành file có thứ tự, chạy lặp lại được. Đó là thư mục supabase/migrations.

ORM

Viết truy vấn bằng code có kiểu thay vì chuỗi SQL. Tiện, nhưng bạn vẫn phải hiểu SQL bên dưới. Bước 2 dùng Drizzle.

Cache, job nền, realtime

Cache

Lưu kết quả đắt để dùng lại. Khó ở chỗ làm mới: khoá cache phải chứa mọi thứ làm kết quả đổi. Repo dùng videoId + ngôn ngữ + promptVersion.

Job nền

Việc lâu (gọi LLM phân tích bài hát) không nên bắt request chờ. Đưa vào hàng đợi, trả về ngay, báo tiến độ sau.

SSE

Server đẩy dữ liệu một chiều về trình duyệt. Hợp với "tiến độ phân tích đang chạy".

WebSocket

Hai chiều, kết nối giữ mở. Hợp với phòng game nhiều người chơi. Bước 5 thay Realtime bằng thứ này.

Rate limit

Giới hạn số lần gọi theo người dùng để chặn lạm dụng và giữ chi phí LLM. Xem consume_usage.

Vận hành

Biến môi trường

Cấu hình và bí mật nằm ngoài code, mỗi môi trường một bộ. Không commit .env.

Log và giám sát

Lỗi production chỉ thấy qua log và công cụ như Sentry (đã có trong repo). Log phải đủ ngữ cảnh nhưng không chứa dữ liệu nhạy cảm.

CI/CD

Mỗi lần push, máy chủ tự chạy lint, test, build rồi deploy. Workflow của chính trang này là ví dụ đầu tiên của bạn.

Docker

Đóng gói app cùng môi trường để chạy giống nhau ở mọi nơi. Bước 1 dùng nó cho Postgres.
